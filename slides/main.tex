\begin{frame}{Model Formulation}
    \small
    The robot movement problem is modeled as a feasibility problem.
    For each pallet layer, the model follows the order of incoming boxes
    and decides how each picked chunk is placed on the pallet.

    \begin{columns}[T,totalwidth=\textwidth]
        \begin{column}{0.50\textwidth}
            \begin{block}{Decision variables}
                \begin{itemize}
                    \item which consecutive boxes form each chunk;
                    \item where each picked chunk is placed;
                    \item which gripper plate opens at release.
                \end{itemize}
            \end{block}
        \end{column}

        \begin{column}{0.46\textwidth}
            \begin{block}{Constraints}
                \begin{itemize}
                    \item chunks have no gaps or overlaps;
                    \item each box is picked and placed exactly once;
                    \item each pick fits within the gripper size;
                    \item each chunk stays within one pallet row;
                    \item the opening side is free at release.
                \end{itemize}
            \end{block}
        \end{column}
    \end{columns}

    \vspace{0.25cm}
    \begin{alertblock}{Goal}
        Find any assignment that defines a feasible pick-and-release plan.
    \end{alertblock}
\end{frame}

%------------------------------------------------

\begin{frame}[fragile]{Chunk Model Parameters}
    \small
    The model inputs are the pallet grid, expressed as the number of boxes along each dimension,
    the box size, the number of boxes, and the gripper capacity.
    From these data, the model derives the maximum number of boxes that can be picked at once
    and the minimum number of necessary chunks.
    \vspace{0.15cm}
    \begin{lstlisting}
par int: n_boxes;
par int: boxes_x_dim;
par int: boxes_along_x;
par int: boxes_along_y;
par int: grip_size;

par int: max_pkble_boxes =
(grip_size + boxes_x_dim) div boxes_x_dim;

par int: chunks_per_row =
(boxes_along_x + max_pkble_boxes - 1) div max_pkble_boxes;

par int: n_chunks = boxes_along_y * chunks_per_row;
    \end{lstlisting}
\end{frame}

%------------------------------------------------

\begin{frame}{Possible Chunk Representation}
    \small
    The chosen representation should be compact, while preserving the fact that a pick is a consecutive interval
    in the belt order.

    \vspace{0.25cm}
    \begin{tabular}{p{0.26\textwidth} p{0.36\textwidth} p{0.30\textwidth}}
        \toprule
        \textbf{Encoding} & \textbf{Representation} & \textbf{Limitation} \\
        \midrule
        Enumerated chunks
        & Store, for each chunk, the list of boxes it contains, using padding for shorter chunks.
        & Chunk structure is explicit, but many variables and extra constraints are needed. \\
        \midrule
        Binary assignment
        & Use one Boolean variable for each pair \((c,i)\), equal to true if box \(i\) is assigned to chunk \(c\).
        & Membership is explicit, but the encoding is large; contiguity and row consistency require extra constraints. \\
        \midrule
        Interval encoding
        & Store only the first box and the length of each chunk.
        & \textbf{Adopted}: compact, and contiguity is implicit. \\
        \bottomrule
    \end{tabular}
\end{frame}


%------------------------------------------------

\begin{frame}[fragile]{Chunking Implementation}
    \vspace{0.10cm}
    \textbf{Variables:} define the interval associated with each chunk.
    \begin{lstlisting}
array[1..n_chunks] of var 1..n_boxes: chunk_start;
array[1..n_chunks] of var 1..max_pkble_boxes: chunk_len;
    \end{lstlisting}

    \vspace{0.10cm}
    \textbf{Start condition:} the first chunk starts from the first box.
    \begin{lstlisting}
constraint chunk_start[1] = 1;
    \end{lstlisting}

    \vspace{0.10cm}
    \textbf{No gaps or overlaps:} each chunk starts immediately after the previous one.
    \begin{lstlisting}
constraint forall(g in 1..n_chunks - 1)(
  chunk_start[g + 1] = chunk_start[g] + chunk_len[g]
);
    \end{lstlisting}

    \vspace{0.10cm}
    \textbf{Coverage:} the last chunk must end at the last box.
    \begin{lstlisting}
constraint chunk_start[n_chunks] + chunk_len[n_chunks] - 1 = n_boxes;
    \end{lstlisting}
\end{frame}

\begin{frame}[fragile]{Placement Variables}
    \small
    Chunks are released in source order (chunk \(g\) is the \(g\)-th pick).
    The model now decides \emph{where} each chunk lands on the pallet and which plate opens during the drop.

    \vspace{0.10cm}
    \textbf{Pallet row:} which row each chunk is assigned to.
    \begin{lstlisting}
array[1..n_chunks] of var 1..boxes_along_y: y_row;
    \end{lstlisting}

    \vspace{0.10cm}
    \textbf{Starting column:} where inside the row the chunk begins.
    \begin{lstlisting}
array[1..n_chunks] of var 1..boxes_along_x: x_start;
    \end{lstlisting}

    \vspace{0.10cm}
    \textbf{Opening side:} select the plate used to release each chunk.
    \begin{lstlisting}
array[1..n_chunks] of var 0..1: plate;
    \end{lstlisting}

    \vspace{0.10cm}
    The value \(\texttt{plate[g]}\) determines which neighboring row must be free
    when chunk \(g\) is released, 0 for the upper neighbor and 1 for the lower neighbor.
\end{frame}

%------------------------------------------------

\begin{frame}[fragile]{Placement Constraints}
    \small
    Three constraints together force the chunks to tile the pallet exactly:
    each chunk stays inside its row, two chunks never share a cell, and every row
    is filled completely.

    \vspace{0.10cm}
    \textbf{Row fit:} the chunk cannot run past the row's right edge.
    \begin{lstlisting}
constraint forall(g in 1..n_chunks)(
  x_start[g] + chunk_len[g] - 1 <= boxes_along_x
);
    \end{lstlisting}

    \vspace{0.10cm}
    \textbf{No overlap:} two chunks in the same row must be column-disjoint.
    \begin{lstlisting}[basicstyle=\ttfamily\tiny]
constraint forall(g1, g2 in 1..n_chunks where g1 < g2)(
  y_row[g1] != y_row[g2] \/
  x_start[g1] + chunk_len[g1] <= x_start[g2] \/
  x_start[g2] + chunk_len[g2] <= x_start[g1]
);
    \end{lstlisting}

    \vspace{0.10cm}
    \textbf{Exact row coverage:} each pallet row is filled completely.
    \begin{lstlisting}[basicstyle=\ttfamily\tiny]
constraint forall(r in 1..boxes_along_y)(
  sum(g in 1..n_chunks)(bool2int(y_row[g] = r) * chunk_len[g])
    = boxes_along_x
);
    \end{lstlisting}
\end{frame}

%------------------------------------------------

\begin{frame}[fragile]{Plate Constraint}
    \small
    When chunk \(g\) is dropped, the row on the side selected by \(\texttt{plate[g]}\)
    must still be empty. Because chunks are released in source order, "still empty"
    means any chunk that overlaps \(g\)'s column footprint in the neighboring row
    must have a \emph{larger} index.

    \vspace{0.10cm}
    \textbf{Plate semantics:}
    \[
        \texttt{plate}[g] = 0 \;\Rightarrow\; \text{opens toward } \texttt{y\_row}[g] - 1
    \]
    \[
        \texttt{plate}[g] = 1 \;\Rightarrow\; \text{opens toward } \texttt{y\_row}[g] + 1
    \]

    \vspace{0.10cm}
    \textbf{MiniZinc implementation}
    \begin{lstlisting}[basicstyle=\ttfamily\tiny]
constraint forall(g, g2 in 1..n_chunks where g != g2)(
  (
    ( (plate[g] = 0 /\ y_row[g2] = y_row[g] - 1) \/
      (plate[g] = 1 /\ y_row[g2] = y_row[g] + 1) )
    /\
    x_start[g2] < x_start[g] + chunk_len[g] /\
    x_start[g2] + chunk_len[g2] > x_start[g]
  )
  -> g2 > g
);
    \end{lstlisting}
\end{frame}

\begin{frame}[fragile]{Solving from Python}
    \small
    The model is solved as a feasibility problem.  Python builds each benchmark instance, sends the parameters to MiniZinc, and reads the four decision arrays from the result.

    \vspace{0.15cm}
    \begin{columns}[T,totalwidth=\textwidth]
        \begin{column}{0.32\textwidth}
            \begin{lstlisting}
solve satisfy;
            \end{lstlisting}

            \vspace{0.2cm}
            No objective function is needed: any satisfying assignment is a valid pick-and-release plan.
        \end{column}
        \begin{column}{0.63\textwidth}
            \begin{lstlisting}[language=Python,basicstyle=\ttfamily\tiny]
model    = Model("model.mzn")
solver   = Solver.lookup("gecode")
instance = Instance(solver, model)

instance["n_boxes"]       = pallet_info["n_boxes"]
instance["boxes_x_dim"]   = boxes_x_dim
instance["boxes_along_x"] = pallet_info["boxes_along_x"]
instance["boxes_along_y"] = pallet_info["boxes_along_y"]
instance["grip_size"]     = grip_size

result = instance.solve()
            \end{lstlisting}
        \end{column}
    \end{columns}
\end{frame}

\begin{frame}{Scaling by Gripper Size}
    \small
    \begin{columns}[T,totalwidth=\textwidth]
        \begin{column}{0.36\textwidth}
            Larger grippers reduce the number of groups that must be scheduled.
            In the benchmark, the average number of groups drops from about \(75\) for \(k=1\) to about \(40\) for \(k=3\).

            \vspace{0.25cm}
            This is reflected in the runtime curves: \texttt{gecode} remains the most stable backend, while \texttt{highs} is consistently slower.

\begin{frame}{Conclusions}
    \small
    \begin{itemize}
        \item The movement planning problem is naturally split into grouping and release scheduling.
        \item The interval encoding keeps grouping compact while preserving the geometric structure of the pallet rows.
        \item Release feasibility can be expressed with local constraints on vertical neighbors and release order.
        \item The benchmark favors CP-oriented solvers, especially \texttt{gecode}.
        \item Larger grippers reduce the number of groups and usually improve runtime.
    \end{itemize}

    \vspace{0.3cm}
    \begin{block}{Final point}
        Any satisfying assignment gives a complete pick-and-release plan that places every box once and releases every group toward free space.
    \end{block}
\end{frame}
